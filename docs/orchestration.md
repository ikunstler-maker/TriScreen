# Режим оркестрації

Оркестрація — це коли головний чат не робить усе сам, а запускає кількох помічників-агентів: одні досліджують і пишуть код, інші незалежно перевіряють. Це дорожче, але для ризикових і великих кроків значно надійніше.

## Як додати в новий проєкт
1. Скопіюйте цей файл у новий репозиторій як `docs/orchestration.md`.
2. У `CLAUDE.md` замініть рядок «No subagents unless the owner asks» на блок з розділу «Блок для CLAUDE.md» нижче.
3. Більше нічого не потрібно: позначки в таблиці плану вже описані в `03-communication-uk.md`.

## Коли вмикати
| Позначка в плані | Коли | Приклади |
|---|---|---|
| **(оркестрація обов'язкова)** | Високий ризик або робота у багатьох файлах/сервісах | Вхід і паролі, доступи, дані користувачів, секрети, гроші, міграції бази, сервер і деплой |
| **(оркестрація рекомендована)** | Складний або великий крок без високого ризику | Новий великий екран, кілька пов'язаних функцій одним пакетом, аудит |
| нічого | Простий крок | Текст, кнопка, дрібне виправлення |

Рішення завжди за вами: позначка — лише порада Claude.

## Як увімкнути (ваші слова)
- «Погоджую план. Починай в режимі оркестрації.»
- «Роби всі три етапи однією хвилею в режимі оркестрації.»
- Без цих слів Claude працює сам, без помічників.

## Ролі агентів
| Роль | Що робить | Коли потрібна |
|---|---|---|
| **Дослідник** | Читає код/документацію сервісу, повертає короткий висновок | Незнайома бібліотека, сервер, чужий API |
| **Виконавець** | Пише код для своєї частини кроку, у своїй ділянці файлів | Крок ділиться на незалежні частини |
| **Перевіряльник (безпека)** | Незалежно шукає діри: доступ, витоки даних, секрети | Завжди при «обов'язковій» оркестрації |
| **Перевіряльник (якість)** | «Не вірю, доки не побачу доказ»: перевіряє кожен пункт «Готово, коли», шукає помилки | Завжди при оркестрації |

Головний чат — диригент: ставить завдання, зводить результати, вирішує суперечки, пише звіт. Перевіряльник отримує код, а не висновок головного чату — щоб не підтверджувати чужу гіпотезу.

## Правила для Claude
- Кожному агенту — чітке завдання: мета, файли, що вже з'ясовано, межі. Агент знає лише те, що йому написали.
- Незалежні агенти запускаються паралельно; виконавці не чіпають ті самі файли.
- Знахідки перевіряльників перевіряються ще раз перед виправленням; хибні відкидаються з поясненням у звіті.
- Розмір: зазвичай 3–5 агентів, до 10 лише для дуже великих кроків. Більше — без окремого дозволу не можна.
- Без режиму оркестрації субагентів не запускати.
- Секрети, паролі й особисті дані агентам не передавати.
- У звіті рядок: скільки агентів, які ролі, що знайшли перевіряльники і що виправлено.
- У файлі рішення кроку записати: «Власниця: «…в режимі оркестрації»».

## Ціна
- Кожен агент витрачає ліміти окремо: оркестрація коштує в рази дорожче за звичайну роботу.
- Тому для простих кроків вона не потрібна, а «рекомендовану» можна пропустити, якщо ліміти на межі.

## Блок для CLAUDE.md
```
## Orchestration
- Subagents only when the owner says «режим оркестрації» for that step (approval does not carry over). Details: `docs/orchestration.md`.
- Plan marks: «(оркестрація обов'язкова)» for high-risk (data, access, sign-in, secrets, money, migrations, deploy) or many files/services; «(оркестрація рекомендована)» for other complex/large steps; nothing for simple ones.
- Roles: researcher, implementer (own file area), security reviewer (always on mandatory), quality reviewer (always). Reviewers get the code, not the conclusion.
- Usually 3–5 agents, ≤10 without separate approval; independent agents in parallel; no secrets to agents.
- Report: agents used, reviewer findings, what was fixed or rejected and why.
```
